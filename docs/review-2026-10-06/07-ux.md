## ① 问题清单（按严重度）

### U-1 [P1] F 键双义：飞行切换与熔炉 UI 同帧双触发

- **位置**：`Assets/Scripts/Unity/Player/PlayerController.cs:558`（`FlightTickToggle`：`Input.GetKeyDown(KeyCode.Space) || Input.GetKeyDown(KeyCode.F)` → `_flight.TryToggle`）；`Assets/Scripts/Unity/UI/CraftingFurnaceUi.cs:19,51-57`（`ToggleKey = KeyCode.F`，开着关自己、关着且无其它模态就开）。
- **现象**：两个组件都只检查 `UiCursorGate.IsOpen`，互相不知道对方存在。游戏内按一次 F：飞行态翻转 **且** 熔炉 UI 弹出同时发生（脚本执行顺序只影响谁先看到门的状态，无法避免双触发组合）。再按 F：门开着 → 飞行不响应，只关熔炉——关掉后人还在飞行态；下次按 F 又是双触发。唯一干净通道是双击空格，但按键表没教（见 U-2）。
- **为什么伤儿童人体工程学**：任务链 `quests/chapter1.json` ch1_07 明确教孩子"按 F 开熔炉"——新手照做就飞上天，且熔炉面板盖在屏幕上、世界冻结感（指针解锁）与飞行叠加，孩子无法建立"F=开熔炉"的因果模型。
- **建议改法**（任选其一，均为小改）：a) 飞行只保留双击空格，`FlightTickToggle` 删掉 `KeyCode.F` 分支；b) 熔炉键改 L（或改为"准星指着熔炉方块按 F 才开"）。改后同步更新帮助菜单按键表与 ch1_07 文案。
- **预期收益**：消除一个新手必踩的"按键幽灵事件"；飞行/熔炉各归其位。
- **证据等级**：[V] 代码级双监听确凿；具体时序组合（先飞后开/同帧）[I] 建议活体验证一次。

### U-2 [P1] 帮助菜单按键表未覆盖 m13 新键，熔炉 F 从未列入

- **位置**：`HelpMenuUi.cs:261-284`（`KeyTableLeft/KeyTableRight`）。
- **现象**：按键表右栏 9 行 = E/P/B/V/X/F11/H/Esc/Alt+F4。**缺失**：F 或双击空格 = 飞行（m13 W1）、R = 武器面板（m13 W4）、F5 = 第三人称（CameraThirdPerson.cs:11）、F = 熔炉（UiCursorGate.cs:8 的注释自己写着"熔炉 F"，但表里从没有）。`Wave1HintLine`（m12 W6 写的）也没提飞行。另外左栏 Shift 写"下蹲 / 潜行"，飞行态下 Shift 实为下降（PlayerController.cs:598），语义未更新。
- **为什么伤**：飞行与武器面板是孩子 2026-08-18 亲口提的需求，落地后孩子却几乎无法发现（R 键零提示；飞行只有 F5 式口口相传）。帮助菜单是本作唯一的按键文档。
- **建议**：右栏补 4 行（"双击空格/F 飞行（空格升 Shift 降）"、"R 武器面板"、"F5 第三人称"、"F 熔炉"——若 U-1 改键则同步）；Shift 说明加"飞行时下降"。
- **收益**：孩子亲点功能的可发现性从零到一；纯文案改动，半天工作量。
- **证据**：[V]。

### U-3 [P1] Esc 层级不可预测：模态 UI 开着按 Esc 叠开暂停菜单

- **位置**：`PauseMenuUi.cs:111-122`（`HandleKey` 只让位死亡画面，不查 `UiCursorGate`）；`ChestUi.cs:24-25` 注释自认"E/Esc 不接：Esc 会与暂停菜单双触发"。
- **现象**：背包/工作台/口袋/熔炉/箱子/武器面板开着时按 Esc → 暂停菜单**叠**在原 UI 上（timeScale=0、指针门计数 +1）。要回到游戏需：Esc（关暂停）→ 再按 E/P/B/F/R（关原 UI）= 三次按键。且点暂停菜单"继续"的那次左键点击落在大etsy数模态 UI 的矩形外，会**顺带触发底层 UI 的点外关闭**（各 UI 的 `ShouldCloseOnMouseDown` 都监听 MouseDown）——一次点击两个 UI 状态变化。
- **为什么伤**：孩子的普遍心智模型是"Esc = 关掉眼前的东西"。这里 Esc 有时关帮助菜单（HelpMenuUi 自己处理 Esc）、有时弹暂停、有时解锁鼠标（PlayerController.cs:775-779，指针锁定时按 Esc 只解锁），三种语义取决于当前状态机，不可预测。
- **建议**：`PauseMenuUi.HandleKey` 在 `UiCursorGate.IsOpen` 时让位（或广播"关闭最上层模态"）；至少保证"Esc 先关模态 UI，全关后再开暂停"这一条统一规则。
- **收益**：Esc 语义收敛为一条规则；从任意 UI 回游戏最多两次按键。
- **证据**：[V] 代码路径完整；叠开时点"继续"是否真触发底层点外关闭取决于 OnGUI 事件顺序 [I]，活体验证。

### U-4 [P1] SHIFT+click 合成入料一次只送 1 个

- **位置**：`CraftGridInteraction.cs:73-84`（`PutMainSlotOne`：`cell = s.WithCount(1); inv.TryRemoveOne(...)`）。
- **现象**：合一把石镐（3 圆石 + 2 木棍）需对同一格 SHIFT+click 5 次；木棍还要先在 2×2 里合一次。MC 的 SHIFT+click 语义是整叠转移。帮助菜单文案（`CraftingShiftHint`）只说"直接放入合成区"，没说一次一个。
- **为什么伤**：这是 m13 P0"孩子说没办法合成"的修复，解决了**可达性**没解决**效率**——孩子点一下只进一个，容易再次得出"还是坏的是"的结论。另外 `TakeBackToMainSlotOne` 要求目标主背包槽为空，被占时静默失败，行为不可预测。
- **建议**：SHIFT+click 改整叠入格（循环 `PutMainSlotOne` 直到格满或该槽清空）；或双击=整叠。取回失败给一次性提示。
- **收益**：合成操作数从 5+ 降到 1；上一次同类挫败的彻底收尾。
- **证据**：[V]。

### U-5 [P2] 火枪装填 1.5s 零反馈

- **位置**：`BlockInteraction.cs:1086-1090`（装填中 `return`，注释明说"不播咔哒"）；对比弓有蓄力条（DrawBowChargeBar:1586-1601）。
- **现象**：开火后 1.5s 内右键静默拒绝。孩子连点右键 = 毫无反应，"枪坏了"错觉。无弹药时有咔哒声 + 但也没有文字提示（弓无箭有"没有箭了"飘字，火枪无弹只有咔哒）。
- **建议**：照弓蓄力条画一个装填条（准星下方，方向反过来填充）；无弹时补一条"没有子弹了"提示（复用 `ShowInteractionHint`）。
- **证据**：[V]。

### U-6 [P2] 世界列表：删除按钮与进入按钮间距 6px、armed 无超时、8 行无滚动

- **位置**：`TitleScreenUi.cs:405-413`（进入按钮 x=cx+56 宽 64、删除按钮 x=cx+126——间隙 6px）；`:411-429`（`_deleteArmed` 无超时复位，换行/点别处不复位）；`:395`（`rows = Math.Min(_worlds.Count, 8)`，无滚动）。
- **现象**：每行"进入"和"删除"几乎贴着；孩子想点进入，手一抖点到删除（有两段确认兜底，第一次点只变红"确认删除?"）。armed 状态永久保持——孩子点了删除又去玩别的行，回来时那行仍处于红确认态，下一次误点即真删（回收站式改名 `.deleted`，孩子无法自行恢复）。
- **为什么伤**：Fitts 定律 + 儿童误操作率——破坏性操作与高频操作的目标相邻且同尺寸同色。8 行上限：孩子 65 个会话若建了 >8 个世界，第 9 个起在世界列表不可见（"我的世界不见了"）。
- **建议**：删除按钮右移 20px+ 并缩小（或挪到行尾悬停展开）；armed 3s 超时自动复位；列表加滚动或"显示全部"。
- **证据**：[V] 代码；用户实际世界数未核（LocalLow 未读，见 ⑦）。

### U-7 [P2] 标题画面按 Esc 弹出暂停菜单

- **位置**：`PauseMenuUi.cs:118-121`（`else if (!DeathScreenVisible()) SetOpen(true)`——没有 `TitleScreenUi.IsVisible` 让位；对比 HelpMenuUi 的 H 有 `UiCursorGate.IsOpen` 挡）。
- **现象**：标题画面（gate 是开着的）按 Esc → 暂停菜单叠在主菜单上、timeScale=0、输入锁叠加。孩子想"退菜单"按 Esc 看到的是"游戏已暂停"盖在标题上。
- **建议**：`HandleKey` 加标题画面让位，或在标题画面禁用 PauseMenuUi 组件。
- **证据**：[V] 代码路径；实机表现 [I]。

### U-8 [P2] 模态 UI 开着时数字键/滚轮仍换 hotbar 选中槽

- **位置**：`HotbarUI.cs:268-283`（`Update` 无 `UiCursorGate.IsOpen` 早退）。
- **现象**：背包/工作台开着时按 1-9 或滚滚轮，选中槽悄悄变化——而普通左键点合成空格的入料源正是"当前选中 hotbar 格"（`CraftGridInteraction.PutSelectedOne`），孩子在背包里滚一下轮子，入料源就变了，下一次点击放进合成区的是别的物品。另外 `WeaponPanelUi.ClickWeaponRow`（165-173）可把选中态设到主背包槽 9..35，此时 hotbar（只画 0..8）**无任何可见选中指示**——孩子不知道手里拿的是什么。
- **建议**：`HotbarUI.Update` 开头加 `if (UiCursorGate.IsOpen) return;`；武器面板选中主背包槽时在 hotbar 区画一个"手持物品小图"或在面板行加更明显的选中态。
- **证据**：[V]。

### U-9 [P2] 空手右键凭空放石头（m3 占位语义）

- **位置**：`BlockInteraction.cs:552-563`（`PlaceHeldItemOrPlaceholder`：无 `blockId` 物品/空手 → 放 `placeBlockId`（默认 Stone）且**不扣物品**）。
- **现象**：空手或手持非方块物品（剑/镐/食物以外的杂物）右键任意面 = 无限生成石头。MC 中空手右键是无操作。
- **为什么伤**：孩子会意外在地形上"长出"石头（误右键）；也解释了世界里可能出现的莫名石块。作为"建造沙盒的福利"可以保留，但至少帮助菜单应说明。
- **建议**：空手右键改 no-op，或放石头时给一次提示；长期看让 `placeBlockId` 占位退役。
- **证据**：[V]。

### U-10 [P2] 色盲与对比度

- **位置/现象**：
  - mob 头顶血条红底 + 绿前景（`MobView.cs:307-315`）——红绿色盲（男性儿童约 8%）难分辨"掉血方向"；
  - hotbar 耐久条绿→红 Lerp（`HotbarUI.cs:235-241`）同问题；
  - `ItemSlotDrawer` 数量角标是纯白字 13px **无底色**（`ItemSlotDrawer.cs:92-100`，对比 `HotbarUI` 有 85% 黑底 `countBg`）——浅色图标上白字对比不足 [I，截图未覆盖此场景]；
  - 经验条绿细条在亮背景对比一般（overworld.png 截图核实）；
  - 等级标签 `Lv N` 11px（`ExperienceBarUi.cs:48-51`）1080p 下偏小。
  - 正面：放置幽灵框蓝/红两态（`PlacementGhostUi.cs:23-26`）蓝红对色盲相对友好；帮助菜单白字深底对比良好（截图核实）。
- **建议**：血条前景加 1px 深描边或改成"红底+白前景"；耐久条低耐久加闪烁；角标照 HotbarUI 加黑底；等级字号 11→14。
- **证据**：[V] 代码 + [I] 部分视觉影响。

### U-11 [P3] 任务完成打勾卡只停 1s

- `QuestHudUi.cs:30`（`CompletedHoldSeconds = 1f`）。孩子在看别处时，"✓ 完成"一闪而过。建议 1→2s（章节解锁卡已是 5s）。

### U-12 [P3] 死亡画面无死因

- `DeathScreenUi.cs:152` 只有"你死了"。摔落/饿死/怪物围殴对孩子的学习价值不同——一行死因（数据在 `PlayerController.TakeDamage` 路径上）可帮孩子归因。

### U-13 [P3] 游戏内无"回主菜单"，只有退出进程

- 暂停/帮助菜单只有"保存并退出游戏"（`Application.Quit`）。换世界必须重启 exe（对比 MC"保存并退回标题屏幕"）。世界管理三态（继续上次/新世界/世界列表）因此每次只能用一次。建议加"保存并回主菜单"（复用 `SaveNow` + `TitleScreenUi` 重显）。

### U-14 [P3] 帮助/暂停菜单固定 720×660，无低分辨率适配

- `HelpMenuUi.cs:338-340`。窗口高度 <700px（低分屏/F11 前的小窗口）时底部溢出。用户全屏原生分辨率下不触发 [I]。

### U-15 [P3] 世界列表 armed 态与"返回"按钮无 Esc 支持

- 标题画面三态（主菜单/新世界/世界列表）均不响应 Esc 返回上一态；种子输入框是 `GUI.TextField`（IMGUI 原生支持退格/方向键/Ctrl+V，输入为整数种子无 IME 需求，够用 [V]）。建议加 Esc=返回。

## ④ 理想交互蓝图（儿童友好规范，供后续里程碑取用）

1. **统一反馈规范**：所有"操作被拒绝"必须有一通道反馈（文字 2s / 音效 / 视觉三选一）——现状火枪装填、取回失败、放床被卡身拒绝都是静默 no-op；所有"成功"已有音效体系，保持。
2. **Esc 单一规则**：Esc = 关闭最上层界面；无界面 = 暂停；标题/死亡画面让位。一处实现（建议在 `UiCursorGate` 上加"当前最上层 UI"栈），所有模态 UI 注册。
3. **危险操作分级**：不可逆（删世界）= 两段确认 + 超时复位 + 按钮分离 ≥24px + 红色；可逆（退出保存）= 红色按钮即可；日常操作永远不给确认弹窗。
4. **按键单一语义**：一个键一个心智模型（F 教训）。新增按键前查 `Input` 全量清单（本报告 ⑥ 可作底稿），并同步三处：代码、帮助菜单按键表、CLAUDE.md。
5. **引导体系**：任务链 desc 已是最佳实践（带按键的具体动作句）；把 m13+ 新系统也编进第二章之后的教学行（`Wave1HintLine` 模式），每加一个大功能补一行 + 一条任务。
6. **儿童点击目标下限**：≥44px 高（现 hotbar 64、主按钮 44 达标；世界列表行按钮 32、武器面板行 28、经验条等级字偏小）。

7. **竞品对标（MC，均为 [I] 推断，未实测 MC）**，按实现成本排序的可借鉴点：
   - 物品栏**拖拽**（本作全程点击式，孩子从 MC 迁移的习惯不成立）——成本高，IMGUI 拖拽要自管 held 栈（ChestUi 已有 `_held` 雏形可扩展）；
   - **配方书**（点击图标自动摆材料）——本作靠记配方 + 帮助菜单，孩子记不住 3×3 摆位；可先做"合成区上方显示目标配方缩略图"低配版；
   - 死亡后**经验损失沟通**（MC 掉经验球有明确视觉）——本作死亡不掉落（m7 设计），反而更儿童友好，不必学；
   - **物品名 tooltip**（悬停显示中文名）——本作所有格子无名称显示，孩子只能认图标；低成本高收益（ItemSlotDrawer 加 hover 检测 + `def.DisplayName`）；
   - **指南针/回主菜单**——见 U-13。

## ⑤ "孩子日常玩一局"路径成本表

| 环节 | 本作操作（证据） | Minecraft 对照 [I] |
| --- | --- | --- |
| 开机→进世界 | 双击 exe → 主菜单 →"继续上次（种子 N）"**1 击**（种子已在跑则免重载，TitleScreenUi.cs:236-239） | 启动器选版本→单人→选世界→进入（3-4 击） |
| 挖一块石头 | 按住左键 1s（木镐）/4s（徒手，BreakTime 矩阵 cs:1330-1355）+ 裂纹五档反馈 | 同量级（MC 石头 1.15s 木镐） |

| 战斗（近战） | 走近 + 左键点 mob（4m 内优先攻击，CombatController） | 同 |
