### P0 诊断结论（2026-08-19 哈里斯子代理 · 已落地）

**根因**：UI 把 hotbar 选中格当作合成网格的**唯一**入料通道，`CraftGridInteraction.PutSelectedOne` 仅读 `inv.GetSelected()`（=`GetSlot(SelectedHotbarIndex)`），主背包 9..35 共 27 格完全没有 SHIFT+click / 拖拽 / 右键快捷送入任何路径入网。配方表（124 份）和 `RecipeDatabase.FindMatch` 排序（shaped→materialCount→id 稳定排序，m11 B 批加固守卫，`RecipeDatabase.cs:40-55` 已健康）全绿，21 个 Recipe dotnet 测试通过。

**三假设验证**：
- ① 入格交互 bug → 不是崩溃 / 脏写，是 UX 缺口——主背包 27 格无入料入口
- ② 新物品无配方 = 预期但无教学 → 部分成立：家具绝大多数**有**配方（bed/chest/door 等），教学文案缺一句"主背包怎么送材料入合成区"
- ③ FindMatch 排序回归 → **排除**：当前排序就是稳定排序改进（m11 B 批加的守卫，专门治 6 板摆两行合门 vs 4 板合工作台的抢匹配），不存在回归

**修复（已落地，代码改动在 working tree 等待评审后 commit）**：
- `CraftGridInteraction.cs` 加 `IsShiftLeftClickIn` / `PutMainSlotOne(inv, ref cell, mainSlotIndex)` / `TakeBackToMainSlotOne(inv, ref cell, mainSlotIndex)` 三个新钩子
- `CraftingInventoryUi.cs` 主背包 27 格加 SHIFT+click → `PutMainSlotOne`；合成格有物品时 SHIFT+click → `TakeBackToMainSlotOne`（最近主背包空格）
- `CraftingWorkbenchUi.cs` 同样加 SHIFT+click + 主背包缩影从 9 格扩到 27 格（行 192-197 旧实现只画 hotbar）
- `HelpMenuUi.cs` 加 `internal const string CraftingShiftHint = "合成技巧：按 SHIFT + 点击背包物品直接放入合成区（不必先移到 hotbar）"`，紧贴 `MiningTierHint` 之后画一行
- `Assets/Tests/EditMode/UI/CraftingGridInteractionTests.cs`（新建）6 个 EditMode 测试钉死契约：主背包→合成区 / 合成区→主背包 / 旧 hotbar 路径不回归 / 主背包目标非空拒绝覆盖 / hotbar 索引走 PutMainSlotOne 拒绝 / 越界索引拒绝
- `HelpMenuUiTests.cs` 加 1 个 EditMode 测试钉死 `CraftingShiftHint` 必须含 SHIFT / 背包 / 合成区 三关键词

**测试基线**：dotnet 933 全绿守住（m11 收官基线 933 → m13 P0 后仍 933，Core 没动只动 Unity + 新增 EditMode 测试）。Unity EditMode 批处理需本机 Unity 2022.3.62f3c1 验证（dotnet 链不编译 `#if UNITY_EDITOR` 的 UI 测试与 Unity 侧代码）。
